Variant 2: UNION-based data extraction. Compare how the same search input is handled in each version.

VULNERABLE

Input is joined into SQL

{{ vulnerable_code }}

The f-string inserts the search term directly into SQL. A quote can end the intended string, and UNION can add rows from another table.

MITIGATED

Input is bound as data

{{ safe_code }}

The query structure is fixed. The search text is bound separately, so SQL syntax in the input is not executed as part of the query.

Root cause

String concatenation puts untrusted input into SQL grammar. Parameterized queries keep SQL instructions separate from user-supplied values.

Other defense-in-depth options

  • Allow-list input validation.
  • Least-privilege database access.
  • Generic user-facing errors and protected diagnostic logs.
  • WAF rules as an additional layer, never a replacement for fixing the query.
  • Stored procedures that use parameters rather than dynamic SQL.
